# 下一步需要实现的内容

## 1. 建立可量化的输入性能基准

### 目标

把“感觉稍慢”和“快速书写掉笔”转化为可重复比较的数据。

### 实现途径

- 固定设备、笔、Obsidian、WebView、测试笔记和 30 笔动作。
- 统计原始 `pointerdown` 数、建立的 stroke 数、保存的 stroke 数和取消事件数。
- 记录从事件时间戳到首帧渲染、笔画结束处理和持久化调度的耗时分位数。
- 诊断采样使用定长环形缓冲区；测试关闭时不更新 HUD、不排序、不序列化。

### 验收标准

- 连续 3 轮每轮 30 笔，原始 down、建立 stroke、保存 stroke 均为 30。
- 每轮保存重开后的总数与界面一致。
- 日志能区分“系统未送达”“插件拒绝”“已建立但未保存”三类丢失位置。

## 2. 清理 Pointer Events 热路径

### 待验证假设

- Input Lab 停止后 HUD 仍持续更新，可能对大量诊断数组做每帧或高频排序。
- 每笔结束调用全量 `documentBounds` 或纸张尺寸计算，并触发布局，可能阻塞下一笔。
- `emitDebug` 若在关键回调前执行，诊断开销可能推迟笔画建立或结束。
- 大量 coalesced/predicted points 的处理和渲染可能占满单帧预算。

以上均是定位假设，不是已确认根因。

### 实现途径

- 通过单变量 A/B 确认根因后，只修改命中的环节。
- `pointerdown` 优先完成校验、capture 和 stroke 建立；非关键诊断延后。
- 避免每个 pointer sample 分配大对象或复制大数组。
- 将纸张扩展改成增量边界更新；布局工作合并到下一帧或空闲时段。
- HUD 限频到固定低频率，Input Lab 结束后恢复并停止所有更新。

### 验收标准

- 第一代 M-Pencil 快速连写无可复现漏笔。
- 30 笔计数连续 3 轮完全一致。
- 关闭 Input Lab 时诊断功能不产生持续定时器、HUD 更新或排序工作。
- 自动化回放几何基线不变，撤销重做正常。

## 3. 修复并证明诊断导出

### 目标

让一次导出产生可定位、可解析、可校验的真实 JSON 文件。

### 实现途径

- 使用 Obsidian Vault API 写入明确的 Vault 相对路径。
- 写入后立即通过 adapter/stat 再检查存在性和大小。
- 成功通知显示实际相对路径；失败通知显示真实异常。
- JSON 包含版本、设备信息、测试起止时间、计数摘要、事件和性能样本，但默认不包含笔记正文。

### 验收标准

- 文件在平板文件系统中真实存在且非零。
- ADB 拉取后 JSON 可解析，版本和字段完整。
- 事件摘要与保存笔画计数一致。
- 记录 SHA-256；重复导出不会静默覆盖无法追踪的旧证据。

## 4. 补齐保存与恢复可靠性

### 实现途径

- 覆盖正常 pointerup、pointercancel、应用切后台和插件卸载时的在途笔画策略。
- 保持现有文档格式兼容，继续验证旧 fixture。
- 对保存调度、重开、撤销重做、删除和压力字段增加回归测试。

### 验收标准

- 保存、重开、重载插件和重启 Obsidian 后笔画数与视觉内容一致。
- 不产生单点脏笔画、重复 ID 或不可解析文档。
- 旧格式 fixture 全部可读，序列化往返稳定。

### 实现途径

- 运行 lint、类型检查、测试、覆盖率和构建。

- 按 `V1_PLAN.md` 执行桌面与平板物理验收。
- 固化最终 artifact、release note、已知限制和回退方法。

### 验收标准

- 自动化门槛全部通过。
- 核心平板场景无阻断缺陷。
- 最终 artifact 与测试版本哈希一致。
- 有明确安装、升级、卸载、恢复和问题收集说明。
