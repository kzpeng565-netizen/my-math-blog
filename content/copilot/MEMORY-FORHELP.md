# 记忆提取规则与维护文档

## 📌 概述

本文档记录了 Copilot Memory Watcher 插件的记忆提取机制，包括正则表达式规则、记忆格式规范，以及如何新增或修改记忆模块。

---

## 🔍 记忆提取的完整流程

### 1. 对话文件格式

每次 AI 对话自动保存为 `.md` 文件，结构如下：

```markdown
---
epoch: 1781053593097
modelKey: "deepseek-v4-pro|deepseek"
topic: "时间盘点"
---

**user**: [prompt 正文，包含 <!--CP-MEMORY-GROUP:路径-->]
[Context: Notes: 相关笔记.md]
[Timestamp: 2026/06/10 09:06:33]

**ai**: 
[AI 回复思考内容]
...回复正文...

<!--MEMORY-->
0. [2026-06-10 09:06]
1. [拓扑复习优先]
2. [精力中等]
3. [刚完成实分析作业]
4. [下午继续拓扑复习]
5. [用户要求时间盘点]
<!--/MEMORY-->
[Timestamp: 2026/06/10 09:06:49]
```

### 2. 提取步骤

插件中的 `extractMemory(content)` 函数按以下顺序提取：

```
步骤 1: 正则匹配 <!--CP-MEMORY-GROUP:([^>]+)-->
        ↓ 提取 group = "copilot/导师记忆-coach"

步骤 2: 按 **ai**: 分割对话內容
        ↓ 只搜索 AI 回复部分，忽略 prompt 正文

步骤 3: 从最后一段 AI 回复向前搜索
        ↓ 正则匹配 <!--MEMORY-->\s*([\s\S]*?)\s*<!--/MEMORY-->

步骤 4: 跳过占位符
        ↓ 若 digest 第一行匹配 ^0\.\s*\[当前，视为未填充，跳过

步骤 5: 返回 {group, digest}
```

---

## 📐 正则表达式详解

### 标记提取正则

| 正则 | 用途 |
|------|------|
| `/<!--CP-MEMORY-GROUP:([^>]+)-->/` | 提取记忆组路径。`([^>]+)` 匹配任意非 `>` 字符，即冒号后的路径 |

### 记忆块提取正则

| 正则 | 用途 |
|------|------|
| `/<!--MEMORY-->\s*([\s\S]*?)\s*<!--\/MEMORY-->/` | 提取 MEMORY 标记中的内容。`[\s\S]*?` 非贪婪匹配任意字符（包括换行） |

### AI 回复分隔

| 代码 | 用途 |
|------|------|
| `content.split('**ai**:')` | 将所有 AI 回复提取为独立段落，忽略 prompt 正文 |

### 占位符检测

| 正则 | 用途 |
|------|------|
| `/^0\.\s*\[当前/` | 检测 AI 是否填充了记忆。若匹配说明 AI 使用原始模板未改动 |

## 📝 记忆格式规范

有效的记忆块必须遵循以下格式：

```markdown
<!--MEMORY-->
0. [当前的时间内容]
1. [导师判断的优先级及原因]
2. [学习状态/情绪]
3. [过去一段从事的工作及效率]
4. [下次对话应关注的内容]
5. [其他关键上下文]
<!--/MEMORY-->
```

### 字段说明

| 索引 | 字段 | 含义 |
|------|------|------|
| 0 | 时间 | AI 知道的当前时间，格式如 `[2026-06-10]` |
| 1 | 优先级 | AI 判断的当前任务优先级和决策理由 |
| 2 | 状态/情绪 | 学习状态和情绪描述 |
| 3 | 工作概要 | 过去一段对话期间的工作内容和效率 |
| 4 | 后续关注 | 下次对话应优先关注的方面 |
| 5 | 关键上下文 | 用户提出的特别要求和上下文 |

### ⚠️ 重要规则

- 每项内容必须在方括号 `[]` 内
- 每项长度 ≤ 20 字
- 必须是方括号格式
- 至少有 6 行（0-5）
- 标记 `<!--MEMORY-->` 和 `<!--/MEMORY-->` 必须独行

## 🆕 如何新增记忆模块

### 方法一：通过插件 UI

1. 打开设置 → Copilot Memory Watcher → 齿轮
2. 在"新建记忆模块"区输入路径（如 `任务管理/睡眠情况分析`）
3. 点击"创建模板"
4. 插件自动生成含 `<!--CP-MEMORY-GROUP:任务管理/睡眠情况分析-->` 标记的文件

### 方法二：手动创建

1. 在 vault 中新建 Markdown 文件 `任务管理/睡眠情况分析.md`
2. 在文件末尾添加：
```markdown
### 💾 记忆锚点
<!--CP-MEMORY-GROUP:任务管理/睡眠情况分析-->
<!--MEMORY-->
0. [当前的时间]
1. [导师判断的当前优先级以及原因]
2. [我的学习状态/情绪]
3. [过去一段对话时间我在做什么事情, 学习效率怎么样]
4. [下次对话应优先关注什么, 给了我什么指令要我接着做]
5. [其它关键上下文, 如我提出了什么要求]
<!--/MEMORY-->
```

### 方法三：在 Prompt 中直接使用

在任意 Custom Command 的 prompt 文件中加入标记，如：

```markdown
### 💾 在结尾完成下一次指导的记忆储存
<!--CP-MEMORY-GROUP:任务管理/睡眠情况分析-->
```

AI 会自动将记忆输出到该路径。

## 🔧 如何修改现有记忆模块

### 修改记忆提取规则

修改 `extractMemory(content)` 中的正则表达式：

- **匹配规则**：正则 `/<!--CP-MEMORY-GROUP:([^>]+)-->/` 匹配 `<!--CP-MEMORY-GROUP:xxx-->`，其中 `([^>]+)` 匹配任意非 `>` 字符
- **要修改**：若需改变记忆格式，修改 `<!--MEMORY-->` 块的正则表达式

### 修改记忆存储位置

直接修改 prompt 文件中的标记路径即可。插件会自动创建对应的 `.md` 和 `.json` 文件。

## 🔄 记忆注入机制

在 prompt 中使用模板变量引用记忆：

```markdown
{[[copilot/导师记忆-coach]]}
```

Copilot 会在对话开始前自动将记忆文件内容注入到 prompt 中。

**注意：** 记忆文件必须存在于 vault 中且为 `.md` 格式。

## 📈 维护建议

- 每季度检查一次 `copilot-conversations/` 目录大小，调整保留天数
- 定期查看记忆文件内容，确保 AI 填充质量
- 若发现某条记忆不准确，可通过 UI 中的"清空"按钮移除
- 备份 `copilot/` 目录中的 `.json` 文件防止意外丢失
