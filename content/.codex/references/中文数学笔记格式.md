# 中文数学笔记格式

本规范来自 `copilot/copilot-custom-prompts/笔记排版.md` 的原始意图，用于生成或整理中文数学笔记、证明解释、例子和反例。

## 核心原则

- 主要使用中文；原文是英文的内容保留英文。
- 尽可能完整保留用户原来的证明内容、看法、表达和批注。
- 只做排版、局部组织和必要的轻微纠错，不随意改变数学内容。
- 发现疑似输入错误或内容错误时，结合上下文判断，并用 `*(修正说明)*` 标注。
- 行内公式使用 `$...$`，行间公式使用 `$$...$$`。
- 公式与正文之间保持紧凑，不加入多余空行。

## 标题层级

如果内容有分节：

- 使用 `# 1.xxx` 表示第一节。
- 使用 `## 1.1 xxx` 表示该节下的重要定理或知识内容。
- 使用 `### 1.1.1 xxx` 表示具体的“证明思路”“证明过程”“讨论”等局部内容。
- “例题”“例1”“Example”等不能作为任何一级分节标题；例子应放在对应知识点下面。

如果内容没有明显分节：

- 只使用 `## 概括知识点或者内容`。

## 定理、定义和强调

重要定理使用 Obsidian callout：

```markdown
> [!Note] 标题
> 内容
```

如果 callout 中有多行公式，每一行都要以 `>` 开头：

```markdown
> $$
> formula
> $$
```

定义和小推论不必单独做标题，通常写成：

```markdown
**定义**：...
**推论**：...
```

重要词汇使用 **加粗内容**。

## 证明解释格式

证明解释应当紧凑，并体现整体思路：

```markdown
**核心想法**：用一两句话概括证明主线。

1. **第一步**：说明这一步要证明什么，或者为什么要引入某个构造。
   具体解释...

2. **第二步**：说明这一步如何推进结论。
   具体解释...
```

要求：

- 每个证明步骤要有简单标记，如 `1.`, `2.`, `首先`, `接下来`, `最后`。
- 复杂构造必须解释其背后的逻辑。
- 不要只堆公式；关键公式后要说明它在证明中的作用。

## 例子和反例格式

例子：

```markdown
**核心想法**：这个例子要说明什么。

**例子**：...

**验证**：
1. ...
2. ...

**说明**：...
```

反例：

```markdown
**核心想法**：这个反例破坏了哪个结论。

**反例**：...

**前提检查**：
1. ...
2. ...

**结论失败**：...
```

## 保留规则

- 保留 `%%批注%%`、`*(批注)*`。
- 保留用户已有的 **加粗内容**。
- 保留用户 **Remark** 之后的内容。
- 不要删除用户原来的证明、想法和评论，除非用户明确要求删除。
