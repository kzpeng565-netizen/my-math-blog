# 中文数学笔记格式

本规范来自 `copilot/copilot-custom-prompts/笔记排版.md` 的原始意图，用于生成或整理中文数学笔记、证明解释、例子和反例。

## 核心原则

- 主要使用中文；原文是英文的内容保留英文。
- 尽可能完整保留用户原来的证明内容、看法、表达和批注。
- 只做排版、局部组织和必要的轻微纠错，不随意改变数学内容。
- 发现疑似输入错误或内容错误时，结合上下文判断，并用 `*(修正说明)*` 标注。
- 行内公式使用 `$...$`，行间公式使用 `$$...$$`。
- 公式与正文之间保持紧凑，不加入多余空行。
- 不使用废弃的颜色标记格式。

## 标题层级

如果内容有分节：

- 使用 `# 1.xxx` 表示第一节。
- 使用 `## 1.1 xxx` 表示该节下的重要定理或知识内容。
- 使用 `### 1.1.1 xxx` 表示一个完整的“证明思路”“证明过程”“讨论”等局部内容。
- 不要把连续证明中的每一步都升级成 `###` 标题；例如“定义候选族 / 取上确界 / 用 MCT / 反证”这类内容，应放在同一个“证明过程”标题下，用编号步骤或加粗标签组织。
- “例题”“例1”“Example”等不能作为任何一级分节标题；例子应放在对应知识点下面。

如果内容没有明显分节：

- 只使用 `## 概括知识点或者内容`。

如果只是局部回答、证明解释、例子构造：

- 不必强行加编号标题。
- 优先使用 **核心想法**、**例子**、**验证**、**说明** 这类加粗标签。
- 如果一段证明本身是连续主线，优先压缩为一个标题，例如 `## 1.3 证明过程` 或 `### 1.2.1 证明过程`，下面用 `1. **步骤名**：...` 展开。

## 定理、定义和强调

重要定理使用 Obsidian callout：

```markdown
> [!Note] 标题
> 内容
```

如果 callout 中有多行公式，每一行都要以 `>` 开头：

```markdown
> $$
> formula
> $$
```

定义和小推论不必单独做标题，通常写成：

```markdown
**定义**：...
**推论**：...
```

重要词汇使用 **加粗内容**。

## 证明解释格式

证明解释应当紧凑，并体现整体思路：

```markdown
**核心想法**：用一两句话概括证明主线。

**证明机制**：
- **正向机制**：说明核心工具如何推出目标结构。
- **反向/唯一性机制**：说明任意候选对象如何被核心工具锁定。
- **关键桥梁**：指出证明中最关键的转化。

1. **第一步**：说明这一步要证明什么，或者为什么要引入某个构造。
   具体解释...

2. **第二步**：说明这一步如何推进结论。
   具体解释...
```

要求：

- 每个证明步骤要有简单标记，如 `1.`, `2.`, `首先`, `接下来`, `最后`。
- 复杂构造必须解释其背后的逻辑。
- 不要只堆公式；关键公式后要说明它在证明中的作用。
- 不要写成逐句验证的流水账；要先告诉读者证明分成哪几块、每块要完成什么任务。
- 如果证明天然分为“存在性/唯一性”“构造/验证”“定义/推出结论”，要显式标出来。
- 如果读者读完仍不能回答“为什么这个定理应该是真的”“关键转化是什么”“最难一步为什么成立”，说明证明解释还没有达到目标。

## 例子和反例格式

例子：

```markdown
**核心想法**：这个例子要说明什么。

**例子**：...

**验证**：
1. ...
2. ...

**说明**：...
```

反例：

```markdown
**核心想法**：这个反例破坏了哪个结论。

**反例**：...

**前提检查**：
1. ...
2. ...

**结论失败**：...
```

## 一小段完整示例

```markdown
## 紧空间到 Hausdorff 空间的连续双射

> [!Note] 定理
> 如果 $X$ 紧，$Y$ 是 Hausdorff 空间，$f:X\to Y$ 是连续双射，那么 $f$ 是同胚。

### 证明思路

**核心想法**：证明 $f$ 是闭映射。紧集在连续映射下仍为紧集，而 Hausdorff 空间中的紧集是闭集。

1. **取闭集**：设 $A\subset X$ 是闭集。由于 $X$ 紧，$A$ 也是紧集。
2. **推出像为闭集**：连续性给出 $f(A)$ 紧；又因为 $Y$ 是 Hausdorff 空间，所以 $f(A)$ 闭。
3. **得到同胚**：因此 $f$ 是闭映射。连续双射若是闭映射，则反函数连续，所以 $f$ 是同胚。
```

## 保留规则

- 保留 `%%批注%%`、`*(批注)*`。
- 保留用户已有的 **加粗内容**。
- 保留用户 **Remark** 之后的内容。
- 不要删除用户原来的证明、想法和评论，除非用户明确要求删除。
