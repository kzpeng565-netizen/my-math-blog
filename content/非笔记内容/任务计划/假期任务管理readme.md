# 假期任务管理说明

本说明仅供 `$task-planner` 规划假期、自由安排期或没有固定课表的阶段使用。旧的 `[[任务管理readme]]` 保留给学期学习规划，不得把其中的课程、考试、四象限或固定课程 DDL 规则套用到假期规划。

## 输入文件

- `[[ToDo-任务集合]]`：待规划事项、项目目标、限制条件和参考材料。
- `[[ToDo-已经规划好的任务]]`：已经生成的 Tasks，用于避免重复。
- 当前请求和任务集合中的有效双链：补充假期范围、固定事件、项目材料与任务范围。

## 内容识别

先把输入内容区分为四类：

1. **可执行动作**：可以直接完成并验收，例如联系教练、投递家教简历。
2. **项目目标**：需要多个阶段才能完成，例如学习遍历论前四章、建立金钱管理流程。
3. **限制与偏好**：用于排期但不生成 Tasks，例如每周三天家教、数学放在高精力日。
4. **建议与参考材料**：用于理解任务但不逐条生成 Tasks，例如投递话术、筛选标准、学习六问。

不要把建议、解释、示例、筛选标准或方法论机械地转换为独立任务。

## 自动项目与类别划分

先识别每个事项服务的共同结果，再把它们归入项目；随后根据项目语义生成简洁类别。类别可以是家教任务、数学学习、驾考事项、生活与外出、个人系统建设，也可以根据实际输入生成其他名称。

- 类别是展示层，用于组织多个相关项目。
- 项目是规划层，表示一个持续结果，例如“家教获客”或“遍历论第一轮学习”。
- 执行包是 Tasks 层，表示同一阶段中可以集中完成的一组动作。

只输出有内容的类别，并按照当前优先级排序编号。不要为了套模板创建空类别。

## 适度聚合

先提取原子动作并分别估时，再决定如何合并；不要让每个原子动作直接变成一条 Tasks。

满足以下条件时优先合并：

- 属于同一项目和同一执行阶段；
- 安排在同一天或同一时间窗口；
- 使用相同地点、工具或工作场景；
- 中间不需要等待外部结果；
- 合并后仍有一个清楚的完成条件；
- 合并后通常为 2–6 🍅，且不超过 8 🍅。

存在以下任一情况时必须拆分：

- 日期、地点或精力类型不同；
- 后一步必须等待前一步或第三方回复；
- 有不同的独立产出；
- 一个阶段完成后可能改变下一阶段决策；
- 合并后超过 8 🍅；
- 合并后任务名需要罗列过多事项才能说明完成条件。

默认每条 Tasks 为 2–6 🍅。同一项目、同一天的多个 1 🍅动作必须优先合并。只有独立预约、固定事件、阻塞后续的必要操作，或无法与其他任务共用场景的短事项，才允许单独保留为 1 🍅。

不要为了达到番茄钟下限而合并无关项目。超过 8 🍅的长期工作应拆成少量阶段任务，而不是拆成大量 1 🍅任务。

## 容量与日期

- 使用用户明确提供的每日或每周容量。
- 没有容量信息时，采用每天最多 8 🍅的默认可排容量；只有用户明确提供更高容量且日程确实支持时才可超过 8 🍅。
- 固定事件、通勤、等待和必要准备都占用容量。
- 排期后逐日汇总番茄钟，任何一天不得超过当日容量。
- 未来 1–7 天生成具体执行包；更远的内容优先写成周里程碑说明。用户明确要求完整假期 Tasks 时，再把里程碑拆成每条不超过 8 🍅的阶段任务。
- `⏳` 表示实际准备执行的日期；`📅` 只表示真实截止日期，不得把周末日期伪装成巨型周任务的 scheduled day。

## 分类输出格式

每次追加一个规划批次，并在批次内使用二级标题分类：

```markdown
# 2026-07-13 假期任务规划

## 1. 家教任务

- [ ] #task 完成家教投递准备（两版简历、证明材料、订单表） [🍅:: 0/6] ⏫ ⏳ 2026-07-13
- [ ] #task 完成首轮投递与反馈筛选（5–8个渠道） [🍅:: 0/3] ⏫ ⏳ 2026-07-14

## 2. 数学学习

- [ ] #task 精读测度保持变换与重现定理并整理笔记 [🍅:: 0/6] 🔼 ⏳ 2026-07-15
```

任务名可以在括号中列出 2–4 个紧密相关的交付物，但不要罗列完整步骤。类别编号根据当次实际分类重新生成。

## 回写与复核

把分类后的 Tasks 和简短规划备注追加到 `[[ToDo-已经规划好的任务]]`。写入前检查：

1. 是否存在同项目、同日期、可合并的多个 1 🍅任务；
2. 是否存在超过 8 🍅且没有合理理由的单条任务；
3. 每一天的总番茄钟是否超过容量；
4. 是否把建议、条件或未确认结果误写成任务；
5. 是否存在没有分类标题的 Tasks 行。

只有成功写入、边界明确且不会破坏其他上下文的源任务单元才可以移除；不确定时保留并依靠重复检查。
