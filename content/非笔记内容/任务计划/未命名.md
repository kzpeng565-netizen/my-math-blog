你的判断基本正确：**当前系统的软件工程完成度很高，但教学智能层尚未成立。**它现在优化的是“可追踪、少幻觉、流程不出错”，而不是“像一个真正懂数学的老师一样迅速理解你的问题并给出有帮助的回答”。

144 个测试、类型检查和数据库迁移全部通过，只能证明代码结构稳定，不能证明教学效果好。

# 一、为什么反而不如未经设计的系统

## 1. 系统把“避免出错”放在了“帮助理解”之前

当前流程是固定节点链：

> 分类 → 定位 → 上下文 → 子图 → 候选回答 → 五个评分器 → 重写或拒绝。

并且教材依据、数学正确性、重点、简化和任务专项都要求达到阈值，否则就重写，最终缩小结论。

这种架构很容易形成以下行为：

1. 没有准确定位教材位置；
    
2. grounding 认为依据不足；
    
3. 数学回答尚未真正生成；
    
4. 系统选择保守拒答；
    
5. 输出一段格式正确但没有帮助的话。
    

截图正是如此。你已经提供了一个完整、自包含的引理陈述，系统完全可以解释 (L^\infty) 和引理的基本含义，却因为无法确认教材位置而停止回答。

这说明当前系统错误地认为：

[  
\text{无法定位教材}  
\Longrightarrow  
\text{无法回答数学问题}.  
]

正确逻辑应该是：

[  
\text{无法定位教材}  
\Longrightarrow  
\begin{cases}  
\text{仍可解释用户提供的数学内容},\  
\text{但不声称了解其在本书中的具体作用}.  
\end{cases}  
]

教材 grounding 应限制**关于教材的断言**，而不是封锁一般数学解释。

## 2. “四种模式选一个”本身就是错误抽象

你的问题：

> 这个引理怎么理解？(f\in L^\infty) 是什么意思？补充基础知识。

它同时涉及：

- 普通伴随阅读；
    
- 符号和基础概念解释；
    
- 引理的整体含义；
    
- 可能还需要稍微解释证明路线。
    

它并不属于一个纯粹的“章节导读”“例子分析”“证明引导”或“习题辅助”。

所以不应该要求系统选中一个互斥模式。应该改成：

```yaml
primary_intent: notation_and_concept_explanation

required_capabilities:
  - explain_notation
  - supply_prerequisites
  - interpret_lemma
  - optionally_outline_proof

interaction_style: direct_explanation
source_requirement: user_quote_sufficient
```

四类或五类工作流可以继续存在，但它们应是**可组合能力**，不是互斥的回答模式。

目前 UI 和运行状态中仍显式维护 `task_type` 与 `focus_ref`，说明工作流仍较依赖事先选定任务和定位对象。

### 应改成两层路由

第一层决定用户此刻需要什么：

- 直接解释；
    
- 苏格拉底式引导；
    
- 证明推进；
    
- 习题推进；
    
- 章节整体导读。
    

第二层决定需要调用哪些能力：

- 教材定位；
    
- 前置知识补充；
    
- 例子联系；
    
- 数学验证；
    
- 历史状态读取。
    

因此，一个回答可以是：

> 以“直接解释”为主，同时调用基础补充和引理解释。

而不是硬塞进某一个 subgraph。

## 3. 教材定位没有利用最强的线索：用户已经贴出的内容

系统当前拥有 FTS5、标签和页码定位，但表现说明它没有建立可靠的**多级来源解析**。

对于截图中的问题，正确定位顺序应当是：

### 第一级：用户明确提供的内容

用户贴出的引理本身就是当前最可靠的数学上下文。

系统应先建立：

```yaml
source:
  type: user_quote
  sufficient_for_general_explanation: true
  sufficient_for_book_structure_claims: false
```

### 第二级：当前 UI 状态

包括：

- 当前打开的书；
    
- 当前章节；
    
- 当前页面；
    
- 最近一次 focus；
    
- 最近查看的教材块。
    

### 第三级：精确检索

对用户引用的文字进行：

- 连续短语匹配；
    
- 定理编号匹配；
    
- 数学符号归一化；
    
- 公式指纹匹配。
    

例如把：

```latex
\int f\,d\mu=\int f\circ T\,d\mu
```

规范化后用于搜索，而不是只依赖原始字符。

### 第四级：带章节偏置的混合检索

评分可以组合为：

# [  
S

w_1S_{\text{exact phrase}}  
+w_2S_{\text{formula}}  
+w_3S_{\text{symbol}}  
+w_4S_{\text{BM25}}  
+w_5S_{\text{chapter proximity}}.  
]

### 第五级：模糊定位

若有两个相近候选，可以自动使用最可能位置作为背景，但不要声称已经准确找到。

只有当用户询问：

> 作者为什么把它放在这里？

而位置仍然不明确时，才需要请求用户确认。

不能因为位置不确定，就拒绝解释 (L^\infty)。

## 4. 五个评分器共同制造了机械化

当前系统把五类评分器并行放在几乎每轮回答后面。

这会产生三个副作用。

### 副作用一：模型开始“为评分器写作”

回答会倾向于包含：

- 明确声明证据强度；
    
- 明确列举依据；
    
- 明确表示不确定性；
    
- 明确总结结构；
    
- 明确给出下一步。
    

每一项单看都合理，叠加后就像报告，而不是自然教学。

项目甚至要求例子分析显式采用几种证据强度措辞。

这种标记适合内部数据，不适合每次暴露在回答里。

### 副作用二：10-gram 复述检测并不能检测“有没有价值”

数学解释天然需要重复：

- 定义名称；
    
- 公式；
    
- 定理条件；
    
- 标准术语。
    

字面重复少，不代表解释好；字面重复多，也不代表只是在复述。

例如解释 (L^\infty)，准确答案必然重复“本质有界”“几乎处处”“可测函数”等教材术语。强行避开这些词，反而容易不自然。

应当把 10-gram 检测降为调试指标，不能作为主要评分依据。

真正需要检测的是：

> 回答除了换一种说法，还增加了什么理解？

例如是否增加：

- 一个关键区别；
    
- 一个具体例子；
    
- 条件的作用；
    
- 前后联系；
    
- 证明中的桥梁；
    
- 用户下一步能做什么。
    

### 副作用三：低风险问题也走重型审查

“(L^\infty) 是什么意思”不需要：

- 五个独立评分器；
    
- 两轮重写；
    
- 缩小结论；
    
- 作者意图审查。
    

它只需要一个优秀数学模型直接回答，再做一次轻量自检。

# 二、截图中合理的回答本来应该是什么样

系统至少应该先直接回答：

> (L^\infty_\mu) 表示在测度 (\mu) 意义下“本质有界”的可测函数组成的空间。这里“本质有界”不是要求函数在每一个点都有限，而是允许在一个零测集上出现例外：存在常数 (M<\infty)，使得 (|f(x)|\leq M) 对 (\mu)-几乎处处的 (x) 成立。

例如，函数在一个零测集上取任意大的值，但其他地方都不超过 1，它在 (L^\infty_\mu) 中仍可视为有界。

这个引理的核心是：

> (\mu) 在 (T) 下不变，等价于“先对 (f) 积分”和“先用 (T) 移动输入再积分”得到同样的结果。

也就是：

# [  
\int_X f,d\mu

\int_X f\circ T,d\mu.  
]

为什么先只要求 (f\in L^\infty)？因为集合的示性函数 (\mathbf 1_A) 都属于 (L^\infty)。取 (f=\mathbf 1_A)，便有

# [  
\int \mathbf 1_A\circ T,d\mu

# \mu(T^{-1}A),  
\qquad  
\int \mathbf 1_A,d\mu

\mu(A).  
]

因此积分等式对所有有界函数成立，特别会推出

[  
\mu(T^{-1}A)=\mu(A),  
]

这正是 (T)-不变性。

如果 (\mu) 已经是 (T)-不变的，那么结论还能从有界函数推广到所有 (L^1_\mu) 函数，也就是所有满足 (\int |f|,d\mu<\infty) 的可积函数。证明时可以用截断函数把一个 (L^1) 函数逐渐近似成有界函数。

这段回答不需要首先知道它在 GTM 259 的具体页码，也不需要作者意图。只有继续回答“它在本章起什么作用”时，才需要定位教材前后文。

## 第四步：撤掉“每轮五评分器全开”

例如例子作用、定理条件、习题提示：

```text

→ 数学正确性检查
→ 帮助性检查
```

## 第五步：重新设计评分器

保留三个真正重要的评价维度。

硬门槛，但只审查实质数学断言。

### 2. 回答价值

- 用户真正问了什么？
    
- 回答是否在开头直接处理了它？
    
- 回答新增了哪些理解，而不只是换词？
    
- 用户读完后是否更容易继续学习？
    
- 哪部分可以删除而不损失理解？

### 3. 教学自然度

检查：

- 是否像在填写模板；
    
- 是否无必要地声明证据等级；
    
- 是否无必要地总结流程；
    
- 是否因为防错而不敢回答；
    
- 是否针对用户当前困惑，而不是展示系统分析。
    

评分器只给反馈。最终数学回复仍由 GPT 生成，不让 DeepSeek直接修改数学内容。

```markdown
   - 直接调用指定数学模型；

2. 重构任务路由：
   - 不再从互斥的 chapter_intro/example/proof/exercise 中强选一个；
```

# 最终判断

现在出现的问题不是项目没有价值，而是它过早完成了“工业化外壳”，却还没有验证最基本的产品假设：

> 经过路由、教材检索、规划和评分后，回答是否真的比直接问 GPT 更好？

接下来必须把这个问题作为最高验收标准。只要 Agent 回答不如 Raw GPT，就优先返回 Raw GPT，而不是因为系统已经走完了复杂流程，就相信复杂流程的结果。
