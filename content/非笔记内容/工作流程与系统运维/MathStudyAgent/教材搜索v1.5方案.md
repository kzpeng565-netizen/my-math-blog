# 教材搜索 v1.5 方案

## 1. 目标与失败证据

v1.5 要解决的不是单纯的 BM25 或 embedding 召回问题，而是检索前没有可靠识别数学术语、关系意图和教材语言。旧版 `TextbookQueryPlanner` 实际上是确定性正则函数；没有命中触发短语时直接返回 `none`。另一条结构兜底又会在没有词法或语义锚点时从全书开头抽取若干同类型对象，导致“相关定理”错误落到与问题无关的早期定理。

四个盲测目标是：

- Radon–Nikodym 导数与换测度：4.4.2，优先 Theorem 4.38、Proposition 4.39；
- 复测度：4.4.3，优先 Theorem 4.43、Proposition 4.44/4.45；
- Fatou 引理与控制收敛定理：Proposition 4.17 和 Theorem 2.21；
- 球面测度：4.3.2，必须能定位定义段 `p86-b300`。

这些问题及答案只存在于测试集，不作为 Prompt few-shot。

## 2. 三级查询理解

每个绑定教材的非导航问题依次组合三个信号：

1. 确定性规则提取编号、对象类型、教材来源要求和关系词；
2. 本地词典用最长匹配识别规范术语、同语言别名、证据块和小节锚点；
3. `deepseek-v4-flash` 关闭 thinking 做快速初筛，只输出 `needs_full_planner`、`should_retrieve_hint` 和枚举理由。

只要存在关系型、多对象、跨语言、歧义、规则冲突、规则无检索结论或初筛失败，就调用完整 Planner。完整 Planner 使用 utility 模型 `deepseek-v4-pro`，结构化输出教材语言检索词、关系意图、对象类型、编号和经过目录校验的小节 ID。规则是不可降低的下限，Planner 不能取消明确的教材检索要求。

简单的同语言单术语或精确编号查询，在词典精确命中、没有关系意图且各信号一致时跳过完整 Planner。

## 3. 导入阶段的语言识别

语言识别发生在教材块落库后、教材进入 `ready` 前。系统将全书按位置分成 20 个桶，从非空桶中公平分配采样额度，最多累计 50,000 个有效字符。只有汉字与 ASCII 拉丁字母计数；数字、空格、标点和公式符号忽略。

- 有效字符少于 1,000：`unknown`；
- 汉字比例至少 60%：`zh`；
- 拉丁字母比例至少 60%：`en`；
- 其余：`mixed`。

数据库保存语言、置信度、两类字符数和采样算法版本。跨语言查询由 Planner 产生教材语言词，再由本地词典和目录校验；回答跟随用户语言，首次出现时括注教材原词。

## 4. 自动数学词典

导入按小节阻塞生成词典。每个小节输入包含标题、块 ID、结构类型、编号和按阅读顺序排列的文本；超过 20,000 字符时按块边界切片，并携带一个相邻块作为衔接。

程序先提取小节标题、定理/引理/公式/导数/测度等显式命名术语和“称为……”结构。模型负责补充隐含概念和同语言别名，不生成跨语言翻译。输出词条必须包含规范术语、别名、类型、定义或陈述块、证据块、连续原文证据和置信度。

程序只接受以下词条：所有块 ID 属于当前小节；短证据去除空白后确实是教材块中的连续原文；定义块也属于输入。若模型遗漏块 ID，但证据原文在本小节内只能唯一定位到一个块，程序可以确定性补回该 ID；零命中或多命中仍然拒绝。验证失败的候选不会写入词典。

首选 `deepseek-v4-flash` 开启 thinking。每小节以程序抽取的显式术语作为质量门禁，模型召回低于 90% 或结构/证据验证失败时，用 `deepseek-v4-pro` 重试一次。两个模型均失败时教材进入 `term_dictionary_failed`，保留已解析块和成功运行；Book Manager 展示进度、失败原因并允许续跑。

抽取运行按小节记录输入哈希、模型、thinking 配置、Schema 版本、状态、结构化结果和错误。未改变且已经成功的小节可复用，失败或输入发生变化的小节重新处理。

## 5. 检索与证据纪律

检索使用规范词、同语言别名、编号和 Planner 的教材语言词分别查询 FTS，再去重合并。词典证据块是强锚点；词典小节只允许补入该小节内的定义、定理、命题和必要段落。

无词法、编号、工作集、词典或语义锚点时，不再从全书顺序抽取同类型对象。Primary 只接受高或中等证据；`candidate_k`、`rerank_k`、`active_k` 均为上限。候选不足时返回更少对象，没有合格对象时返回 `unresolved`。

## 6. 状态、数据与界面

教材导入状态为：

```text
parsing → detecting_language → building_term_dictionary → ready
                                             ↘ term_dictionary_failed
```

`books` 保存语言统计和词典进度；`math_terms` 保存合并后的证据词条；`math_term_extraction_runs` 保存逐小节运行。数据库由 Alembic 0008 升级，不能依赖 `create_all` 为既有数据库补列。

Book Manager 显示语言、置信度、词典状态、完成小节数和错误，并为失败教材提供“重试词典生成”。模型直调写入模型日志，可按 `textbook_query_triage`、`textbook_query_plan` 和 `textbook_term_extraction` 检查 Prompt 与结果。

## 7. 验收

- 四个 golden 查询全部命中正确小节，前三类尽量命中指定定理或命题，球面测度必须包含定义段；
- 系统 Prompt 中不得出现四个 golden 查询的示例答案；
- 覆盖 50,000 字符上限、分桶抽样、中英文和短文本；
- 覆盖证据拒绝、Flash 到 utility 重试、幂等续跑和阻塞失败；
- 覆盖规则已命中但关系型问题仍进入 Planner、初筛失败时保守规划，以及简单精确查询跳过完整 Planner；
- 覆盖跨语言检索、无锚点不填充和预算不凑数；
- 完整 pytest、Ruff、mypy 与迁移测试通过。

## 8. 长期边界

方案 3 不属于 v1.5 的初始查询链路。未来可以允许 GPT-5.5 high 在生成过程中最多申请一次受控补充检索，但检索范围、证据门槛、对象预算和失败返回仍由程序执行。参见 [[教材搜索问题的解决-方案总览]]。

## 9. 研究依据

- [Mathematical Information Retrieval](https://aclanthology.org/C16-1221/)：类型词典、最长序列匹配和查询扩展；
- [A Comparative Study of Query and Document Translation for Cross-Language Information Retrieval](https://aclanthology.org/1998.amta-papers.41/)：跨语言查询与文档翻译；
- [SQLite FTS5](https://www.sqlite.org/fts5.html)：FTS5 词元化、短语与扩展机制；
- [Qwen3 Embedding](https://arxiv.org/abs/2506.05176)：多语言与跨语言文本检索能力。
