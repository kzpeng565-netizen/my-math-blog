# MathStudyAgent 当前系统问题

> 本文记录已经由代码核对确认的问题，以及仍需继续排查的系统薄弱点。它描述的是当前实际实现，不把设计文档中的目标架构当作已经接线的功能。

## 1. 质量评价策略容易过度打回

用户确认的产品规则：软教学建议至少做到两条；少于两条时允许触发一次定向改写。但软建议不能覆盖数学正确性，也不应要求每个回答机械完成全部教学维度。

需要明确区分：

- 硬失败：明确数学/事实错误、影响结论的关键证明缺口、完全没有回答核心问题、明确教材事实与高置信原文冲突、高风险结论未完成必要验证。
- 软建议：工具选择动机、简单问题、一般情形、迁移价值、聚焦程度、认知负担、下一步抓手等。
- 软建议计数不足两条时，最多触发一次定向教学改写；不得进入循环重写。

当前 `QUALITY_REVIEW_SYSTEM_PROMPT` 只被定义，默认 v2 工作流没有调用它，因此现阶段既没有可靠的语义质量复核，也没有真正执行“至少两条软建议”的机制。

## 2. AnswerContract 当前几乎没有实际约束力

`AnswerContract` 的设计目的，是在生成回答前形成一张内部最低任务清单，说明本轮核心目标、必须回答的事项、教材证据要求、是否先推导以及是否需要完整细节。它不应成为用户可见的固定模板。

当前实现的问题：

- `core_goal` 基本只是原样保存用户问题；
- 普通问题的 `must_answer` 通常只有“直接回答用户提出的核心问题”；
- 证明问题只追加“说明证明主线和关键转折”“解释关键步骤”等通用要求；
- 没有根据具体问题提取障碍、所需性质、工具作用、输出深度和真正的子目标；
- 当前没有结构化模型 Router 为它补充语义拆解。

因此它目前更多是一个形式存在的对象，尚不能稳定指导或检查回答是否真正解决了用户的具体卡点。

## 3. 确定性质量检查作用很弱

当前 `preliminary_quality_check` 主要检查：

- 回答是否非空且不少于 24 个字符；
- 在要求先推导的回答中，是否出现“显然”“不难看出”“由某引理可得”“细节略”等关键词。

这些检查无法理解语义：

- 正常模型回答几乎不会因为少于 24 个字符而失败；
- 出现“显然”不一定表示真的省略关键步骤；
- 不出现这些词也不代表证明没有缺口；
- 无法判断回答是否解释了真正困难、工具选择或定义动机。

更严重的是，当前实现直接设置：

```python
factually_and_mathematically_correct=True
source_claims_supported=True
```

也就是说，现有确定性检查并未真正验证数学正确性，也没有验证教材断言是否有证据。

## 4. 本轮目标识别主要依赖关键词和正则表达式

当前默认 v2 流程直接调用 `classify_rule_floor`，按“定位/页码”“检查证明”“完整证明”“证明思路”“求解”等关键词选择固定意图，并分配预设的能力、推理深度和风险。

实际情况：

- `Primary Intent` 由关键词分支决定；
- `Capabilities` 是各分支预设的固定列表；
- `Source Requirement` 主要由“教材、书中、原文、作者、这一页”等词和精确编号正则决定；
- `Reasoning Depth` 与 `Risk` 按分支固定；
- `Confidence` 主要根据文本长度、有限的指代词、精确编号和显式动作判断。

虽然 `ROUTER_SYSTEM_PROMPT` 和 `merge_router_output()` 已经存在，但默认 v2 工作流没有调用结构化模型 Router。因此 Canvas 中“模型识别本轮目标”的描述目前属于设计目标，不是当前实际运行机制。

## 5. “为什么这样”“思路是什么”容易识别错误

当前规则不能稳定识别以下问题：

- 为什么这样定义？
- 为什么要引入这个构造？
- 为什么这里要使用紧致性？
- 思路是什么？
- 这个方法是怎么想到的？

如果问题没有同时包含“证明”“证明思路”“怎么想到”等已登记关键词，它通常会落入默认 `explain_concept`，只获得 `recall_general_math + teach_pedagogically`，推理深度为 `local`，不会明确要求重建动机链或先进行数学推导。

仅修改 `TUTOR_SYSTEM_PROMPT` 可以提高回答质量的概率，但不能保证路由、AnswerContract 和后续评价稳定要求这项能力。

## 6. 待继续审计

- 教材检索的真实触发条件是否过窄；
- SourceResolver 设计与当前 `_load_v2_context` 实现之间的差距；
- 质量 Prompt、定向重写和结构化 Router 为什么尚未接线；
- 还有哪些模块处于“接口/模型已定义，但核心行为仍很初级”的状态。
