# 半小时行为解释系统——架构与维护

<!-- ai_provenance: source=codex; date=2026-07-24; verification=checked; retrieved_notes="" -->

## 1. 第一版目标

第一版每半小时分别清洗电脑和手机使用数据，保存两份独立事实摘要，再把它们交给 DeepSeek V4 Flash 解释。系统只生成报告，不弹窗、不修改计划、不调用 Cold Turkey 或手机管控。

```text
电脑 ActivityWatch SQLite ─→ computer_facts
                                      ┐
                                      ├→ DeepSeek → ai_report
                                      │
手机 foreground/screen/heartbeat ─→ phone_facts
                                      │
                         可选的时间重叠事实
```

系统在每小时 `03` 和 `33` 分运行，分析刚结束的半小时，给同步留出约三分钟。

## 2. 为什么保留两个独立事实层

- 电脑 AFK 不等于休息，可能正在使用手机；
- 手机亮屏不等于娱乐，可能是在通信、查资料或操作工具；
- 两套采集器的缺失和延迟不同；
- 独立保存后，整天分析可以复用，不必再次读取全部原始事件；
- AI 判断错误时，可以定位是电脑提取、手机提取、跨设备比较还是模型解释的问题。

跨设备层只计算时间重叠，例如“电脑非 AFK 且手机亮屏多少分钟”，不直接判断分心。

## 3. 文件职责

| 文件 | 职责 |
|---|---|
| `config/settings.json` | 数据路径、模型、标题长度、应用显示名 |
| `prompts/half-hour-interpreter.md` | 约束 AI 区分事实、推断和建议 |
| `src/computer_facts.py` | 电脑事件去重、AFK处理、网页与窗口合并 |
| `src/phone_facts.py` | 手机JSONL去重、亮灭屏与前台应用重建 |
| `src/cross_device.py` | 计算两台设备的客观时间重叠 |
| `src/deepseek_client.py` | 调用 DeepSeek JSON API |
| `src/run_half_hour.py` | 组织一次完整处理并保存文件 |
| `tests/test_cleaning.py` | 检查标题、隐私清洗和时间段合并 |
| `systemd/*` | 树莓派半小时定时任务 |

## 4. 输出位置

树莓派运行副本：

```text
/home/conrad/workspace/activitywatch-advisor
```

输出：

```text
data/
├── computer_facts/YYYY-MM-DD/HH-MM.json
├── phone_facts/YYYY-MM-DD/HH-MM.json
├── combined_facts/YYYY-MM-DD/HH-MM.json
├── ai_reports/YYYY-MM-DD/HH-MM.json
├── ai_reports/YYYY-MM-DD/HH-MM.md
└── state/processing-state.json
```

`computer_facts` 和 `phone_facts` 是以后整天分析优先复用的数据；`ai_reports` 是模型解释，不应代替事实层。

## 5. 清洗原则

电脑端：

1. 以 `(starttime, data)` 合并 aw-sync 的增长版本；
2. AFK冲突时，以更晚开始的状态为准；
3. 只把 `not-afk` 时段计入窗口活动；
4. 浏览器优先使用 Web Watcher 的域名和标签页标题；
5. Web Watcher缺失时退回窗口标题，不强行分类。

手机端：

1. 合并 archive 与 incoming，并按事件内容去重；
2. 由 screen 事件重建亮灭屏时段；
3. 只有亮屏后出现的新 foreground 事件才认定为当前前台应用；
4. 用 heartbeat 判断采集器是否仍然在线；
5. 不把亮屏、微信或哔哩哔哩直接解释为行为动机。

发送给 AI 前会清除标题中的未读数量、浏览器后缀、邮箱、手机号和长标识符。完整 URL 不发送，只保留域名。

## 6. 密钥

真实 API 密钥不在本目录中。树莓派使用：

```text
/home/conrad/.config/activitywatch-advisor/env
```

该文件权限必须为 `600`。`.env.example` 只有占位符。

## 7. 常用检查

查看定时器：

```bash
systemctl status activitywatch-advisor.timer --no-pager
systemctl list-timers activitywatch-advisor.timer --no-pager
```

查看最近运行：

```bash
systemctl status activitywatch-advisor.service --no-pager
journalctl -u activitywatch-advisor.service -n 50 --no-pager
```

手动处理最近一个完整半小时：

```bash
sudo systemctl start activitywatch-advisor.service
```

重新处理指定时段：

```bash
cd /home/conrad/workspace/activitywatch-advisor
python3 src/run_half_hour.py \
  --start 2026-07-24T19:00:00+08:00 \
  --end 2026-07-24T19:30:00+08:00 \
  --force
```

## 8. 当前边界

- 第一版没有读取任务计划；
- 不自动推送每份半小时报告，避免形成新的打扰；
- 不进行全天归因，只保存可复用事实层；
- 应先观察三至七天，再决定是否增加计划对照和报告查看页面；
- API密钥曾在聊天中出现，部署验证后应在 DeepSeek 控制台轮换。
