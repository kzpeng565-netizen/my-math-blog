## P0：先保证不会丢存档或误锁网站

1. **备份已建立，仍需恢复演练。** Pi 每分钟用 SQLite backup API 原子生成快照，经 Syncthing send-only → receive-only 同步到 `D:\MyFocusGardenArchive`，电脑端保留 staggered 版本。下一步应择机做一次停服恢复演练。
2. **素材排除清单已补齐。** `.gitignore` 已覆盖 plants、mushrooms 与 blocks PNG；仍不得仅依赖 Git ignore 作为发布审查。
3. **保持安全测试入口。** 自动测试和 UI 调试必须用 `FOCUS_GARDEN_DRY_RUN=1`；增加测试证明正式配置不会在 CI 或测试环境误调用 Cold Turkey。
4. **完善失败语义。** 当前多个 block 中只要一个 Pi 介入执行成功，就会发“接受介入”奖励；而本地专注要求全部 block 不失败。应决定是否统一为“全部目标成功”，并把规则写成测试。

## P1：提高数据准确性与可解释性

- 早睡目前只看手机最后活动。可加入电脑、平板最后活动和次日早晨边界作为交叉条件，同时保留“估计”措辞与质量字段。
- 给每种奖励规则增加配置化的 `enabled`、阈值、版本和解释，不再把规则完全写死在 `pi_sync.py`。
- 保存同步游标或让 Pi 生成稳定的奖励摘要，避免每次扫描全部历史目录。
- 在 UI 中分别展示“源事件时间”和“种植时间”，避免日/周/月/年筛选口径被误解。
- 增加奖励审计详情：源路径、规则版本、为何满足、为何未满足；敏感字段仍不得进入前端。

## P1：收紧架构与可靠性

- 为 SQLite 加 schema version 和显式迁移；新增字段时提供升级与回滚测试。
- 清理 `static/app.js` 中被后续覆盖的旧版 `renderGarden` 和 `openPlant`，拆成 API、状态、奖励、花园、弹窗等模块。
- 静态文件找不到时当前会回退到 `index.html`；应让缺失 PNG/CSS/JS 返回 404，避免素材错误伪装成成功响应。
- 增加配置 schema 校验，启动时一次列出错误的植物 ID、重复 ID、缺失贴图、未知类别和不在 allowlist 的 block。
- 增加跨重启、休眠、系统时钟变化、并发种植、数据库损坏与 SSH 超时测试。
- 为正式进程增加单实例锁和清晰的“退出游戏”入口，避免只打开浏览器却不知道后台仍在运行。

## P2：花园与玩法

- 继续调整大尺寸花园的方块密度、植物遮挡、阴影方向和背景融合；重点测试 `7×7`、`9×9`、`15×15`。
- 支持按奖励类型限制或推荐种类，例如早睡偏向蘑菇、专注偏向花，但保留用户最终选择权。
- 增加稀有度、成长阶段、季节和图鉴进度时，先保持奖励账本与视觉层分离，避免改画面时破坏历史数据。
- 增加“撤销最后一次种植”需要新状态和审计记录，不能直接删除奖励。
- 原创替换素材时保持稳定 `species_id`，这样历史存档无需迁移。

## P2：产品体验

- 对 SSH 同步显示上次成功时间、耗时和错误摘要，而不是只有“正常/失败”。
- 展示 Cold Turkey 实际执行到哪些 block；开始前明确锁定通常不可撤销。
- 增加键盘操作、焦点样式、减少动画选项和色彩对比检查。
- 统计页可增加“主动接受介入次数”“AI 完成闭环次数”“早睡达标天数”“专注分钟与奖励数”的趋势图，并明确统计口径。

## 发布前必须完成

当前项目只适合本机个人使用。若未来要上传 GitHub、发给朋友、放到网盘或发布，应先：

1. 替换全部 Minecraft、Mushroom Nook 和其他非原创素材；
2. 清理存档、日志、主机名和本地路径；
3. 加入许可证、依赖清单、安全审查与全新安装测试；
4. 若允许非本机访问，为 API 增加认证、CSRF 防护和明确的网络暴露方案。
