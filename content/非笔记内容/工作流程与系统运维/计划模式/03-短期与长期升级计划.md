## 1. 升级原则

升级按“证据先于自动化”推进。资料和真实反馈不足时，优先显示未知、收集证据和改进可观察性，不扩大模型权限。任何阶段都保持：Goal Agent 与 Next Action 独立、Obsidian 插件唯一写入、重大计划边界由用户确认、Garden 只在 Tailnet 内访问。

## 2. 短期：0–7 天

目标是完成第一次真实课程闭环，而不是继续增加输入字段。

- [x] 三门课教师、教材、大纲和考核比例已录入；考试日期继续保持未知；
- [x] 四个学习目录、`教材pdf` 和课程档案已授权，45 份资料完成同步和 FTS；
- [x] 微分几何 `1.1.md` 已完成 MathInk 可见层适配；
- [ ] 为微分几何第一节课选择真实授课小节并逐项填写 0–3 掌握度；
- [ ] 概率论和泛函分析上完第一节课后重复同一输入；
- [ ] 为数学所与抽象代数补充真实题源；在此之前保持待核验；
- [ ] 只确认少量推荐日，验收 task-sync 与 Obsidian 写回，不一次性接受全部 12 项；
- [ ] 每次课程学习后提交最小反馈：授课小节 + 掌握度 + 深度分钟 + 阻塞；
- [ ] 观察 2026-09-06 20:30 首次自然周复盘和 ntfy receipt；
- [ ] 如首周真实题源仍不足，继续保留等待状态，不允许虚构题组。

系统层升级：

- 增加资料同步年龄、最后成功索引时间和目录授权变更提示；
- 在 UI 上把“推荐日”“已确认日”“已写入 Obsidian”三种状态进一步区分；
- 为通知保存最小 receipt，避免重复推送；
- 为 Tavily 刷新展示抓取时间、正文哈希变化和“往届参考”标识。

## 3. 短期：4 周灰度试运行

### 每周验收

| 周次 | 核心问题 | 通过条件 |
|---|---|---|
| 第 1 周 | 课程输入和任务链能否真实运行 | 三门课实际授课小节已填写；至少一次任务写回和一次完成归因 |
| 第 2 周 | 计划量是否过高或过低 | 有完整深度分钟记录；不把欠账全部滚入下一周 |
| 第 3 周 | 轨道权重是否符合真实风险 | 依据成绩或练习证据在同月内重新排序，理由可追溯 |
| 第 4 周 | 22–31 小时范围是否可持续 | 4 次周复盘均有版本；至少三周数据可比；不修改容量范围本身 |

### 灰度退出门槛

只有同时满足以下条件，才建议把功能开关从试运行改为长期启用：

- 无任务丢失或重复；
- 所有进度结论可追溯到证据；
- 资料不足时没有虚构预测；
- 4 次周复盘都生成可回退版本；
- 自动修改只发生在允许范围；
- 重大修改均进入审批；
- 用户认为反馈成本可以持续。

若未通过，保持现有数据和版本，暂停自动调整，只保留只读评估和手动计划，不删除历史。

## 4. 中期：2026-10 至 2027-01

### 学习功能

- 课程总评面板加入“已知权重、当前区间、达到 90 所需后续平均分”和最敏感考核项；
- 数学所题源增加来源指纹与重复检测，防止同卷不同文件名被当成不同题源；
- 遍历论把章节、习题、读书笔记、讲解和问题单做成可核验交付物，而不是只累计时长；
- 抽象代数分别保存书面题组 streak 和口头四维评分，并提供最近错误类型分布；
- 增加跨周间隔复习队列，但推荐日仍由用户确认。

### 系统质量

- 建立一组固定、脱敏的 Goal Agent 回归情景，验证资料不足、落后、突发考试和容量下降；
- 记录模型建议被接受、拒绝、回退的比例，用于发现过度调整，不用于给用户评分；
- 对自动 patch 做 schema、总分钟、每日上限、权重和跨月边界的第二层验证；
- 对资料更新做增量索引与失效标记，避免全文重复处理；
- 增加 SQLite 定期一致性检查和只含结构数据的恢复演练。

## 5. 中长期：2027-02 至 09

- 当年正式通知发布后，官方 A 级来源替换往届参考，并通过审批修改硬截止日期；
- 春季选拔、夏令营、九月推免分别成为条件分支，不提前假设某条路线一定存在；
- 导师联系只生成草稿、准备问题和材料清单，不自动发送邮件或提交申请；
- 限时笔试记录增加完整模拟条件、环境和题源质量，避免只看分数；
- 面试准备增加口头追问记录、复盘和不同评价者之间的一致性；
- 形成可导出的目标档案：计划版本、证据、来源、成绩情景和未核验事项，但不导出模型私密配置。

## 6. 长期系统升级方向

### 6.1 预测校准

当样本充足后比较“Agent 预测”与真实周完成量，报告误差区间。若预测长期偏高，先调整短期承诺，不自动扩大或缩小用户确认的 22–31 小时范围。

### 6.2 策略实验

一次只实验一个可逆策略，例如题组顺序、复习间隔或周内分布。保存开始时间、假设、评价指标和回退条件；课程总评、正式申请和关键考试期不做高风险实验。

### 6.3 多目标能力

只有当前单目标经过一个完整学期稳定运行后，才考虑多 Portfolio。首版不增加生活、作息、人文课或夜间 Agent 工作制，避免资源竞争和提示词污染。

### 6.4 模型与供应商可替换

保持确定性计算、权限校验、SQLite 和 API 与模型解耦。当前 Goal Agent 固定为 `gpt-5.6-sol` Responses/medium；Next Action 与其他系统模型不随之切换。未来更换模型时先跑固定回归集，不让模型迁移改变任务数据或审批规则。

### 6.5 灾难恢复与可移植性

补充 Goal SQLite 的一致性备份、加密异机副本和逐版本恢复演练。任何恢复都先比较生产树，禁止把 Windows 开发镜像当成 Pi 权威源。

## 7. 不应升级成什么

- 不把深度分钟变成自我价值评分；
- 不用单一综合百分比掩盖证据缺口；
- 不因落后一周就把全部欠账搬到下一周；
- 不根据传闻自动改招生硬要求；
- 不让 AI 绕过用户确认安排具体日期；
- 不把 Goal Agent 变成 Next Action 的聊天别名；
- 不自动联系导师、提交报名或执行其他外部行动。
