## 1. 这套模式解决什么问题

目标模式不是另一个 Next Action。它是一个独立的长期目标控制层，用证据回答三件事：

1. 距离目标还有多远，哪些部分仍然未知；
2. 当前周计划是否按真实吞吐量推进；
3. 当证据变化时，应如何修改短期策略和长期路线。

Next Action 继续只回答“现在最值得做哪一步”；Goal Agent 负责月里程碑、周承诺、进度证据、风险判断和策略调整。二者不共享提示词、聊天记录或数据库，只通过已有任务及其完成证据联动。

## 2. 总目标与四条轨道

总目标是“2028 级保研到中国科学院数学与系统科学研究院何伟鲲方向”。系统内的执行终点暂定为 `2027-09-30`，等待 2028 级正式通知发布后再确认。

| 轨道 | 资源权重 | 当前验收口径 |
|---|---:|---|
| 概率论、泛函分析、微分几何 | 40% | 三门课程总评分别不低于 90；考核比例未知时不生成虚假预测 |
| 数学所笔试 | 20% | 在不同真实题源下连续 3 次限时成绩不低于 120/150 |
| 遍历论与导师交流准备 | 30% | `2027-01-31` 前完成双方确认章节与真实习题，并形成 3–5 页笔记、20–30 分钟讲解和一页问题单 |
| 抽象代数笔试与面试 | 10% | 不同真实题组连续 3 轮书面正确率不低于 80%，口头四项均不低于 4/5 |

轨道权重是资源分配，不是把四项压成一个“总进度百分比”。页面分别显示内容覆盖、真实题源掌握、周执行、吞吐量预测、证据置信度和状态。

## 3. 深度学习预算

- 周一至周五每天 2–3 小时；
- 周六、周日每天分别 6–8 小时，并拆为 3–4 个深度时段；
- 正常周容量 22–31 小时，基准 26.5 小时，即 1590 分钟；
- 课程作业、证明、习题和需要持续推理的集中阅读计入；资料搬运、简单整理和轻量阅读不计入深度预算，但仍可记录实际耗时；
- Agent 可依据最近两周真实吞吐量在 22–31 小时内调整下一周承诺，修改容量范围本身必须获得用户确认。

按当前权重，正常周建议范围为：专业课 8.8–12.4 小时、数学所笔试 4.4–6.2 小时、遍历论 6.6–9.3 小时、抽象代数 2.2–3.1 小时。初始周使用中点 26.5 小时。

## 4. 计划层级与交互

```text
总目标 → 月里程碑 → 周承诺 → 推荐日 → 用户确认后写入任务系统
```

- 周任务先进入“本周池”，推荐日期只是建议；
- 用户点击“确认这一天”后，Goal Agent 才通过 task-sync 创建或更新任务；
- Pi 只写 mutation queue，桌面 Obsidian 插件仍是唯一 Markdown 写入者；
- 新的 Obsidian 快照确认写入后，Goal Agent 才把映射标记为同步完成；
- 直接在 Obsidian 中完成任务时，Windows 导出器提供稳定 `task_id` 和完成事件，Goal Agent 可以归因到原计划项。

页面包含六个视图：总览、本周任务、月度路线、证据与资料、AI 对话、版本历史。

## 5. Agent 可做与不可做

Goal Agent 可以自动修改：

- 同月内的周任务；
- 推荐日期；
- 任务拆分；
- 低价值事项的先后顺序。

以下变化必须形成 ApprovalRequest，用户批准后才生效：

- 总目标；
- 截止日期；
- 四轨道资源权重；
- 每日或每周容量范围；
- 重大跨月移动。

所有自动修改都必须保存原因、证据、前后差异和计划版本。回退不会删除历史，而是从旧快照生成一个新的回退版本。

## 7. 首次使用顺序

1. 在 [[../../任务计划/目标模式资料清单]] 中勾选确实允许 Goal Agent 读取的资料，并填入 Vault 内相对路径；
2. 打开 Focus Garden 的“目标模式 → 证据与资料”，确认资料已经被索引；
3. 先提交课程资料、真实题源和教材范围，再决定是否接受推荐日期；
4. 每次深度学习后提交耗时、完成量、得分或正确率、困难度、信心、阻塞和变化；
5. 周日 20:30 查看完整复盘、计划差异和待批准修改；
6. 4 周试运行结束后，依据真实数据决定是否继续启用以及是否调整权重或容量范围。

## 8. 明确排除

本目标模式不包含作息统计、批量寻找教材并转 Markdown、人文课抢课、额外的开学自学安排或夜间固定 Agent 工作制。它们不进入 Goal Agent 的目标、预算、提示词、任务或资料检索范围。
