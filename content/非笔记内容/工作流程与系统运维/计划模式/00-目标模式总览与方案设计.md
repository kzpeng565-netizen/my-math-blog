## 1. 这套模式解决什么问题

目标模式不是另一个 Next Action。它是一个独立的长期目标控制层，用证据回答三件事：

1. 距离目标还有多远，哪些部分仍然未知；
2. 当前周计划是否按真实吞吐量推进；
3. 当证据变化时，应如何修改短期策略和长期路线。

Next Action 继续只回答“现在最值得做哪一步”；Goal Agent 负责月里程碑、周承诺、进度证据、风险判断和策略调整。二者不共享提示词、聊天记录或数据库，只通过已有任务及其完成证据联动。

## 2. 总目标与四条轨道

总目标是“2028 级保研到中国科学院数学与系统科学研究院何伟鲲方向”。系统内的执行终点暂定为 `2027-09-30`，等待 2028 级正式通知发布后再确认。

| 轨道 | 资源权重 | 当前验收口径 |
|---|---:|---|
| 概率论、泛函分析、微分几何 | 40% | 三门课程总评分别不低于 90；考核比例未知时不生成虚假预测 |
| 数学所笔试 | 20% | 在不同真实题源下连续 3 次限时成绩不低于 120/150 |
| 遍历论与导师交流准备 | 30% | `2027-01-31` 前完成双方确认章节与真实习题，并形成 3–5 页笔记、20–30 分钟讲解和一页问题单 |
| 抽象代数笔试与面试 | 10% | 不同真实题组连续 3 轮书面正确率不低于 80%，口头四项均不低于 4/5 |

轨道权重是资源分配，不是把四项压成一个“总进度百分比”。页面分别显示内容覆盖、真实题源掌握、周执行、吞吐量预测、证据置信度和状态。

## 3. 本学期课程进度口径

概率论、泛函分析、微分几何在 2026-08-31 所在周开始上课。课程轨道分为两条互不混淆的通道：

- **启动任务**：在 syllabus、授课小节或作业尚未齐全时，允许从已授权教材、既有笔记和相邻目标中安排可回退的预习/基础复习；它只证明“完成了该学习块”，不能证明“课内已讲完”或“课程掌握度提高”。
- **课内任务**：必须等待真实授课小节或真实作业出现，再按课堂进度生成；不预填章节、不虚构作业和截止日期。

课内任务继续采用以下闭环：

```text
用户确认本周实际授课小节
  → Goal Agent 检索已授权笔记的可见 Markdown / LaTeX / MathInk 识别文字
  → 用户为每个小节填写 0–3 掌握度
  → 生成定义与定理复述、证明重建、当前章节习题和间隔复习
  → 后续成绩到来后再计算达到总评 90 所需成绩
```

掌握度固定为：0 未接触；1 听过或能看材料；2 能复述定义/定理；3 能独立证明或解题。文件修改时间、课时表和笔记数量不能自动证明“已学完”。

三门课程档案已部分确认，教师、教材、大纲和考核比例已录入；考试日期仍未知。大纲中的总课时与详细分配冲突会显示警告，计划以实际授课进度和掌握度为准。

## 4. 深度学习预算

- 周一至周五每天 2–3 小时；
- 周六、周日每天分别 6–8 小时，并拆为 3–4 个深度时段；
- 正常周容量 22–31 小时，基准 26.5 小时，即 1590 分钟；
- 课程作业、证明、习题和需要持续推理的集中阅读计入；资料搬运、简单整理和轻量阅读不计入深度预算，但仍可记录实际耗时；
- Agent 可依据最近两周真实吞吐量在 22–31 小时内调整下一周承诺，修改容量范围本身必须获得用户确认。

按当前权重，正常周建议范围为：专业课 8.8–12.4 小时、数学所笔试 4.4–6.2 小时、遍历论 6.6–9.3 小时、抽象代数 2.2–3.1 小时。初始周使用中点 26.5 小时。

## 5. 计划层级与交互

```text
总目标 → 月里程碑 → 周承诺 → 推荐日 → 用户确认后写入任务系统
```

- 周任务先进入“本周池”，推荐日期只是建议；
- 用户点击“确认这一天”后，Goal Agent 才通过 task-sync 创建或更新任务；
- Pi 只写 mutation queue，桌面 Obsidian 插件仍是唯一 Markdown 写入者；
- 新的 Obsidian 快照确认写入后，Goal Agent 才把映射标记为同步完成；
- 直接在 Obsidian 中完成任务时，Windows 导出器提供稳定 `task_id` 和完成事件，Goal Agent 可以归因到原计划项。

页面包含六个视图：总览、本周任务、月度路线、证据与资料、AI 对话、版本历史。

## 6. Agent 可做与不可做

Goal Agent 可以自动修改：

- 同月内的周任务；
- 推荐日期；
- 任务拆分；
- 低价值事项的先后顺序。

以下变化必须形成 ApprovalRequest，用户批准后才生效：

- 总目标；
- 截止日期；
- 四轨道资源权重；
- 每日或每周容量范围；
- 重大跨月移动。

所有自动修改都必须保存原因、证据、前后差异和计划版本。回退不会删除历史，而是从旧快照生成一个新的回退版本。

## 8. 模型与资料边界

- Goal Agent 独立使用中转站 `gpt-5.6-sol`、Responses API、`medium` 推理；
- 中转站不接受 JSON Schema 时，只在同一模型和同一 Responses 协议内退回提示词 JSON 契约，绝不回退到 DeepSeek；
- Next Action、行为报告和语义分析的模型路由保持不变；
- `几何/微分几何/1.1.md` 已验证为“普通 Markdown/LaTeX + MathInk 笔迹块”格式：可见文字和公式进入索引，压缩笔迹与 base64 不进入；
- MathInk `<!--inkedmark-text-->` 忠实识别段和标准相对图片引用可被读取；图片二进制、画布坐标和布局注释不上传。

## 9. 首次使用顺序

1. 已授权四个学习目录、`教材pdf` 和 [[../../任务计划/目标模式课程档案]]；新增范围仍需在 [[../../任务计划/目标模式资料清单]] 明确勾选；
2. 打开 Focus Garden 的“目标模式 → 证据与资料”，确认资料已经被索引；
3. 已经上课的课程先选择实际讲到的小节并填写 0–3 掌握度；尚未上课或资料未齐时执行启动任务，但课内任务仍不允许提前写入；
4. 每次深度学习后提交耗时、习题尝试/正确数、定义或证明复述、困难度、信心、阻塞和变化；
5. 周日 20:30 查看完整复盘、计划差异和待批准修改；
6. 4 周试运行结束后，依据真实数据决定是否继续启用以及是否调整权重或容量范围。

## 10. 明确排除

本目标模式不包含作息统计、批量寻找教材并转 Markdown、人文课抢课、与四条轨道无关的大规模额外自学或夜间固定 Agent 工作制。为避免等待课程信息时空转，允许在既定轨道和周容量内安排短小、可核验、可随真实授课进度让位的启动任务。
