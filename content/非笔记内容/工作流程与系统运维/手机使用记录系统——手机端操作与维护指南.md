# 手机使用记录系统——手机端操作与维护指南

<!-- ai_provenance: source=codex; date=2026-07-24; verification=user-confirmed; retrieved_notes="" -->

> [!summary]
> 本文记录 Android 手机上 Automate 采集、保存和上传应用使用事件的现行配置。本文中的“已部署”内容已经在手机与树莓派之间实际测试；“计划改进”不应被当作当前功能。

> [!warning]
> 当前私有 Automate flow 二进制包含实时上传 token，不能提交到公开仓库或普通客户端 release。它的私有路径与哈希已记录在 `D:\PiClientMigration\releases\2026.08.07-r1\mobile\automate\PRIVATE-FLOW-REFERENCE.md`；更换手机时应私下导入，并在加密备份建立后轮换 token。完整迁移顺序见 [[Pi系统手机端与电脑端迁移配置流程]]。

配套文档：[[手机使用记录系统——树莓派端操作与维护指南]]

## 1. 系统目标

手机端只负责采集最少量的事实数据：

- 前台应用发生变化的时间与包名；
- 手机进入可交互或不可交互状态的时间；
- Automate 流程仍在运行的心跳；
- 每 15 分钟将当天三个文件上传到树莓派。

手机端不采集：

- 页面文字、输入内容或聊天内容；
- 通知正文；
- 浏览器网址；
- 位置、联系人、短信和通话记录；
- 全局触摸轨迹；
- 屏幕截图。

系统目前把“息屏”视为确定未使用，把“亮屏且可交互”视为可能使用。长时间没有触摸不等于离开手机，因此没有采用“30 秒无触摸即空闲”的规则。

## 2. 数据流

```text
前台应用变化 ─┐
              ├─→ 当天 JSONL 文件 ─→ HTTPS PUT ─→ 树莓派
亮屏/息屏变化 ┤
              │
15 分钟心跳 ──┘
```

手机本地目录：

```text
Documents/PhoneUsage/
├─ YYYY-MM-DD-foreground.jsonl
├─ YYYY-MM-DD-screen.jsonl
└─ YYYY-MM-DD-heartbeat.jsonl
```

例如：

```text
2026-07-24-foreground.jsonl
2026-07-24-screen.jsonl
2026-07-24-heartbeat.jsonl
```

旧版无日期文件可能暂时仍存在：

```text
foreground.jsonl
screen.jsonl
heartbeat.jsonl
```

旧版文件只用于迁移和补传。确认新版按日期文件完整运行一天且树莓派归档正常后，可以手动删除。

## 3. 所需应用与权限

应用：

```text
Automate
开发者：LlamaLab
包名：com.llamalab.automate
```

当前流程需要的权限：

- 访问屏幕内容并观察操作：供 `App foreground` 判断前台应用；
- 管理所有文件：写入 `Documents/PhoneUsage`；
- 查看网络连接与完整网络访问：上传文件；
- 显示通知：显示长期运行状态；
- 忽略应用休眠或电池限制：提高后台存活率。

不需要授予：

- 位置；
- 联系人；
- 短信；
- 通话记录；
- 通知内容读取。

> [!warning]
> Android 无障碍权限本身能力较宽。当前流程只使用它判断前台应用包名，不应再加入读取界面文字、自动点击或截屏等无关模块。

## 4. 当前流程结构

流程名称：

```text
Phone Usage Logger
```

总体结构：

```text
Flow beginning
→ File make directory
→ 初始化当天 foreground 文件
→ 初始化当天 screen 文件
→ Fork 1
   ├─ OK  → 前台应用支路
   └─ NEW → Fork 2
              ├─ OK  → 屏幕状态支路
              └─ NEW → 心跳和上传支路
```

三个长期运行的 fiber：

1. 等待前台应用变化；
2. 等待设备可交互状态变化；
3. 写入心跳、上传三个文件并等待 15 分钟。

两个 `Fork` 都应启用 `Stop with parent`。`NEW` 支路不能连接回 `Fork`，否则会不断创建新 fiber。

## 5. 启动和初始化模块

### 5.1 Flow beginning

流程入口，不需要额外配置。

### 5.2 File make directory

`Path` 使用公式模式：

```text
storage("documents", "PhoneUsage")
```

用途：确保 `Documents/PhoneUsage` 目录存在。

### 5.3 初始化当天文件

两个 `File write` 分别创建当天前台应用文件和屏幕状态文件，避免在尚未产生事件时上传报 `NoSuchFileException`。

`Content`：

```text
""
```

必须勾选 `Append`，这样已有文件不会被清空。

前台应用文件路径：

```text
storage("documents", "PhoneUsage/" ++ dateFormat(Now, "yyyy-MM-dd") ++ "-foreground.jsonl")
```

屏幕状态文件路径：

```text
storage("documents", "PhoneUsage/" ++ dateFormat(Now, "yyyy-MM-dd") ++ "-screen.jsonl")
```

## 6. 前台应用支路

### 6.1 App foreground

配置：

```text
Proceed：When changed
Package：留空
Activity class：留空
Foreground package：pkg
Foreground activity class：留空
```

连接：

```text
Fork 1 的 OK
→ App foreground
```

`YES` 连接到前台事件 `File write`；`NO` 直接连接回同一个 `App foreground`。

### 6.2 前台事件 File write

`Content` 使用公式模式：

```text
jsonEncode({
  "timestamp": dateFormat(Now, "iso8601"),
  "device": "phone",
  "event": "foreground",
  "package": pkg
}) ++ "\n"
```

`File` 使用公式模式：

```text
storage("documents", "PhoneUsage/" ++ dateFormat(Now, "yyyy-MM-dd") ++ "-foreground.jsonl")
```

其他设置：

```text
Charset：UTF-8
Decode：None
Append：勾选
```

写入完成后直接连接回 `App foreground`。原有的逐事件 `Log append` 调试模块已经删除，避免 Automate 自身日志快速增长。

### 6.3 重复记录

微信等应用在内部页面切换时，可能连续产生相同包名：

```text
com.tencent.mm
com.tencent.mm
com.tencent.mm
```

这不是故障。手机端不做复杂去重；树莓派接收端会对完全相同事件去重，后续统计程序还应合并连续相同包名区间。

## 7. 屏幕状态支路

### 7.1 Device interactive

配置：

```text
Proceed：When changed
```

连接：

```text
Fork 2 的 OK
→ Device interactive
```

含义：

- `YES`：设备处于可交互状态，通常为亮屏且可操作；
- `NO`：设备不可交互，通常为息屏或休眠。

### 7.2 亮屏 File write

`Content`：

```text
jsonEncode({
  "timestamp": dateFormat(Now, "iso8601"),
  "device": "phone",
  "event": "screen",
  "state": "on"
}) ++ "\n"
```

`File`：

```text
storage("documents", "PhoneUsage/" ++ dateFormat(Now, "yyyy-MM-dd") ++ "-screen.jsonl")
```

勾选 `Append`，写入后连接回 `Device interactive`。

### 7.3 息屏 File write

`Content`：

```text
jsonEncode({
  "timestamp": dateFormat(Now, "iso8601"),
  "device": "phone",
  "event": "screen",
  "state": "off"
}) ++ "\n"
```

`File` 与亮屏模块相同：

```text
storage("documents", "PhoneUsage/" ++ dateFormat(Now, "yyyy-MM-dd") ++ "-screen.jsonl")
```

勾选 `Append`，写入后连接回 `Device interactive`。

## 8. 心跳和上传支路

### 8.1 心跳 File write

连接：

```text
Fork 2 的 NEW
→ 心跳 File write
```

`Content`：

```text
jsonEncode({
  "timestamp": dateFormat(Now, "iso8601"),
  "device": "phone",
  "event": "heartbeat"
}) ++ "\n"
```

`File`：

```text
storage("documents", "PhoneUsage/" ++ dateFormat(Now, "yyyy-MM-dd") ++ "-heartbeat.jsonl")
```

勾选 `Append`。流程启动时会立即写入一条心跳，此后每次 15 分钟循环再写一条。

### 8.2 Failure catch

心跳写入后连接 `Failure catch`：

```text
Retry limit：1
Failure type：failure_type
Failure message：failure_message
```

`OK` 进入三个 HTTP 上传模块。`FAIL` 进入保留的 `Upload failed` 日志，然后连接到 `Delay`。

该模块主要捕获断网、DNS、连接超时和文件不存在等执行异常。HTTP 服务器返回 `401` 或 `400` 时不一定会走 `FAIL`，因此修改密钥或路径后仍应主动检查 HTTP 状态码和树莓派日志。

### 8.3 三个 HTTP request

上传顺序：

```text
foreground
→ screen
→ heartbeat
```

共同配置：

```text
Request method：PUT
Request content type：Text（UTF-8）
Request content body：留空
Timeout：30 秒
Save response：Don't save
```

前台应用 URL：

```text
https://pi.taild4d3f7.ts.net/upload/foreground.jsonl
```

前台应用 `Request content path`：

```text
storage("documents", "PhoneUsage/" ++ dateFormat(Now, "yyyy-MM-dd") ++ "-foreground.jsonl")
```

状态码变量：

```text
status_fg
```

屏幕状态 URL：

```text
https://pi.taild4d3f7.ts.net/upload/screen.jsonl
```

屏幕状态 `Request content path`：

```text
storage("documents", "PhoneUsage/" ++ dateFormat(Now, "yyyy-MM-dd") ++ "-screen.jsonl")
```

状态码变量：

```text
status_screen
```

心跳 URL：

```text
https://pi.taild4d3f7.ts.net/upload/heartbeat.jsonl
```

心跳 `Request content path`：

```text
storage("documents", "PhoneUsage/" ++ dateFormat(Now, "yyyy-MM-dd") ++ "-heartbeat.jsonl")
```

状态码变量：

```text
status_hb
```

三个模块的 `Request headers` 均使用公式模式：

```text
{
  "X-Upload-Token": "在此填写树莓派 token.txt 中的密钥"
}
```

> [!danger]
> 文档中不得记录真实上传密钥。不要把密钥发到聊天、截图、公开仓库或 Quartz 网站。密钥只应保存在树莓派私有文件与 Automate 请求头中。

### 8.4 上传失败日志

当前只保留失败日志，成功日志已删除。

`Message` 可使用：

```text
"upload failed | type=" ++ failure_type ++ " | message=" ++ failure_message
```

连接：

```text
Failure catch 的 FAIL
→ Upload failed
→ Delay
```

### 8.5 Delay

正式设置：

```text
Proceed：Inexact
Duration：900 秒
Wake up：勾选
```

连接：

```text
最后一个 HTTP request 的 OK
→ Delay
→ 心跳 File write
```

`Wake up` 允许系统在休眠时调度流程，但不会点亮屏幕。Android 可能对后台定时进行少量延迟，只要心跳没有连续缺失 30 分钟以上，通常不需要追求整点精确。

## 9. 网络与 Clash

手机日常使用 Clash 连接外网。Android 通常只能同时运行一个 VPN，因此手机没有再安装或连接 Tailscale VPN。

当前上传方式：

```text
Automate
→ 普通 HTTPS
→ Tailscale Funnel 公网入口
→ 树莓派本机接收服务
```

这与 Clash 可以同时使用，已经在移动网络下实际测试成功。

不要将 URL 改回：

```text
http://192.168.0.229:8765/
```

原因：

- `192.168.0.229` 是家庭局域网动态地址，搬到学校后会变化；
- 接收服务已加固为只监听树莓派本机 `127.0.0.1:8765`；
- 局域网不能直接访问 8765；
- HTTP 不提供传输加密。

## 10. 启动、停止与日常检查

### 10.1 正常启动

1. 确认三个 HTTP request 的上传路径都指向当天日期文件。
2. 点击 `START`。
3. 正常情况下会有三个长期 fiber。
4. 打开几个应用、息屏再解锁一次。
5. 等待一次上传或重启流程触发立即上传。

### 10.2 正常停止

点击：

```text
STOP
```

两个 `Fork` 均启用 `Stop with parent` 时，三个 fiber 会一起停止。

修改流程前必须先停止旧实例，避免新旧配置同时运行。

### 10.3 手机端快速自检

检查：

```text
Documents/PhoneUsage/
```

当天应存在三个文件。正常现象：

- `heartbeat` 至少每约 15 分钟增加一行；
- 切换应用后 `foreground` 增加；
- 息屏和解锁后 `screen` 增加两行；
- 前台和屏幕文件在刚启动且尚无事件时可以是 0 行；
- Automate 运行日志中没有连续失败。

### 10.4 清理 Automate 自身日志

Automate 的流程运行日志与 JSONL 数据文件无关，可以从流程详情菜单选择 `Clear log`。

清理运行日志不会删除：

- 前台应用事件；
- 屏幕事件；
- 心跳；
- 树莓派归档。

## 11. 后台保活

应在手机系统中为 Automate：

- 允许自启动；
- 允许后台活动；
- 关闭电池优化或设为不限制；
- 允许显示常驻通知；
- 在多任务界面锁定，避免一键清理；
- 启用 Automate 的 `Run on system startup`。

系统更新、Automate 更新或手机重启后，应检查：

1. 常驻通知是否出现；
2. 流程是否自动启动；
3. 心跳文件是否继续增长；
4. 树莓派是否继续每 15 分钟收到上传。

## 12. 数据格式

### 12.1 前台应用

```json
{"timestamp":"2026-07-24T17:00:00+08:00","device":"phone","event":"foreground","package":"com.tencent.mm"}
```

### 12.2 屏幕状态

```json
{"timestamp":"2026-07-24T17:05:00+08:00","device":"phone","event":"screen","state":"off"}
{"timestamp":"2026-07-24T17:15:00+08:00","device":"phone","event":"screen","state":"on"}
```

### 12.3 心跳

```json
{"timestamp":"2026-07-24T17:15:00+08:00","device":"phone","event":"heartbeat"}
```

JSONL 的一行必须是一个完整 JSON 对象。不要手工在对象内部换行。

## 13. 本地文件保留与清理

### 13.1 当前已部署状态

手机端已经按天生成文件，但尚未部署自动删除流程。文件会每天新增三份，因此仍需定期检查存储空间。

建议当前采用：

- 保留最近 14 天；
- 只删除已经在树莓派归档中确认存在的日期；
- 永远不要删除当天文件；
- 删除前先停止流程；
- 删除后重新启动流程。

按当前数据量，手机文件通常很小；无需每天清理，可每月检查一次。

### 13.2 旧版无日期文件

确认以下条件后可以删除旧版无日期文件：

1. 新日期文件已完整运行至少一天；
2. 树莓派当天 `archive/YYYY-MM-DD/` 中三类数据均存在；
3. 旧心跳已经补传并合并；
4. 没有待排查的上传故障。

### 13.3 计划中的自动清理

尚未实施。建议后续建立独立的小流程：

```text
Flow beginning
→ Time await（每天约 03:10）
→ Failure catch
→ File delete（删除 15 天前的三个日期文件）
→ 回到 Time await
```

可研究使用的路径公式：

```text
storage(
  "documents",
  "PhoneUsage/" ++
  dateFormat(Now - 15 * 86400, "yyyy-MM-dd") ++
  "-*.jsonl"
)
```

正式实施前必须验证 `File delete` 的通配符匹配结果，防止误删当前文件。

## 14. 常见故障

### 14.1 `NoSuchFileException`

原因：

- 当天文件尚未创建；
- HTTP request 路径日期或文件名写错；
- 初始化空文件模块被删除；
- `fx` 模式或引号错误。

处理：

1. 保留两个初始化 `File write`；
2. 确认心跳在上传前写入；
3. 比较写入路径和上传路径是否完全一致；
4. 确认路径使用蓝色公式模式。

### 14.2 公式显示 `Expected EOF`

URL 或普通文字被放入公式模式但未加引号。

处理：

- URL 使用普通文本模式；或
- 公式模式下把完整 URL 放进双引号。

路径公式、JSON 字典和请求头必须使用公式模式。

### 14.3 日志原样显示公式

表示输入框仍是普通文本模式，或者整个表达式被外层引号包住。

正确表达式开头不应出现多余的整体引号。

### 14.4 HTTP 401

表示上传密钥不一致。

处理：

1. 不要把密钥发到聊天；
2. 在树莓派本地读取 `token.txt`；
3. 更新三个 HTTP request 的 `X-Upload-Token`；
4. 重新上传；
5. 在树莓派日志中确认返回 200。

### 14.5 HTTP 400

常见原因：

- JSONL 某一行不是合法 JSON；
- 缺少 `timestamp`；
- 时间戳无法解析；
- 上传到了不允许的文件名。

不要反复覆盖手机文件。先保留原文件，再查看树莓派服务日志中的错误行号。

### 14.6 连接超时或 DNS 失败

检查：

- Clash 是否正常；
- 浏览器能否打开 `https://pi.taild4d3f7.ts.net/health`；
- 手机是否有网络；
- 树莓派是否在线；
- Tailscale Funnel 是否开启；
- Automate 是否获得网络权限。

### 14.7 心跳中断

若连续 30 分钟以上没有心跳：

1. 查看 Automate 是否仍在运行；
2. 检查电池和后台限制；
3. 检查手机是否重启；
4. 查看失败日志；
5. 检查网络；
6. 在树莓派查看最近上传时间。

### 14.8 前台记录很多但屏幕记录很少

可能是正常使用过程中频繁切换应用。若直接息屏和解锁仍没有 `off/on`，再检查 `Device interactive` 的 `When changed` 和两条回线。

## 15. 当前限制

### 15.1 跨午夜补传尚未实施

目前每次只上传“当天日期文件”。如果最后一次上传发生在 23:45，而 23:45 至午夜之间又产生事件，午夜后流程会开始上传新一天文件，这一小段旧日数据可能只留在手机。

改进方向：

- 每轮先上传昨天文件，再上传今天文件；
- 或每天午夜后执行一次昨天文件终结上传；
- 上传前使用 `File exists`，避免昨天文件不存在时终止支路。

### 15.2 没有自动检查三个状态码都为 200

当前网络异常由 `Failure catch` 处理，但 HTTP 401/400 可能仍沿正常路径继续。后续应增加状态码判断：

```text
status_fg = 200
且 status_screen = 200
且 status_hb = 200
```

否则写入失败日志或发送通知。

### 15.3 没有手机端自动清理

当前需要人工删除已确认归档的旧日期文件。参见第 13 节。

### 15.4 亮屏不等于持续使用

视频、阅读、导航等场景可能长时间无应用切换，但仍在使用；手机放在桌上亮屏也可能被高估。后续汇总应把长期无变化的亮屏区间标记为 `possibly_idle`，不要直接删除。

### 15.5 Android 后台限制

系统升级或省电策略变化后，流程可能被终止。心跳只能发现问题，不能保证系统永不杀后台。

## 16. 修改流程时的检查清单

修改前：

- 停止所有 fiber；
- 截图保存当前流程图；
- 不删除旧 JSONL；
- 记录修改目的。

修改后：

- 检查所有 `File write` 都勾选 `Append`；
- 检查路径的 `fx` 模式；
- 检查两个 `Fork` 不在循环中；
