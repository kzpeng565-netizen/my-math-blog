# 树莓派课程表导入与系统适配

2026-08-31 部署。课表由用户提供的《中国科学院大学.ics》导入，课程数据的唯一运行时权威在 Advisor；花园只通过固定的 Pi 内部代理读取。

## 使用规则

- 默认按课表出勤，不核验出勤，不根据课表推断授课章节或掌握程度。
- 每次课程的保护区间为开课前 20 分钟至下课，课后不额外预留。
- 课程只作安排背景，不增加学习时长、番茄数、任务完成数或花园奖励。
- 工作日每天 180 分钟、周末每天 480 分钟和每周 22–31 小时仍是课外深度学习预算，不扣除课时。
- 不新增课前推送，不执行 ICS 中的 VALARM，不改变现有通知和公网暴露边界。

相同来源校验值重复导入返回 `unchanged`。新文件完整解析成功后才原子替换 `current.json`；失败保留现有版本。运行时读取新版本不需要重启服务。文件权限为 600，数据子目录为 700。

解析器支持本次 WakeUpSchedule 导出的定时单次事件，以及有 UNTIL 的 WEEKLY/INTERVAL 规则，处理上海时区和 UTC 截止时间。目前不支持 EXDATE、RDATE、RECURRENCE-ID、其他频率或全天事件；遇到这些内容明确报错，不能当作导入成功。运行时数据损坏显示不可用，保留既有非课表功能。

## 接口与各系统行为

两个地址读取同一数据：

- [Advisor 课表接口](https://pi.taild4d3f7.ts.net:8450/api/course-schedule)
- [花园课表接口](https://pi.taild4d3f7.ts.net:8460/api/course-schedule)

`GET /api/course-schedule?date=YYYY-MM-DD` 返回从指定日期起七天的课程，省略日期时使用上海当天。日期参数只改变所选周；`today`、`current`、`next` 和实时保护状态始终对应当前上海时间。

主要字段：`available/status`、`counts`、`coverage`、`source_sha256/imported_at`、`events/today/current/next`、`protected_intervals/protection/minutes_until_protection`、`daily_load`、`conflicts`、`policy`。`daily_load.protected_minutes` 对重叠保护区间取并集，仅表示课程安排负担，不属于学习统计。

Next Action 的状态快照带 `course_schedule`。保护区间内，或剩余空档连最短允许行动都放不下时，确定性返回 `source=course_schedule`、`read_only=true`、`decision_type=no_action`、`duration_minutes=0` 的课程提示。课程提示不调用行动模型，不进入接受、完成或待反馈流程。生成、模型返回后、备用建议、追问和接受旧建议时均检查课程约束。已经开始的任务不会自动终止，其正常结果仍可记录。

Goal Agent 的状态增加本周课表。三门专业课与对应习题课使用现有 course_id，其余课程只占用安排时间，不新增目标轨道。初始推荐日的同等候选考虑课程负担；既有复盘允许把尚未确认的推荐日移到课程较少的同周、同月日期，保持原预算和版本审计。导入不触发计划重写，已确认日期不被模型或课表调整覆盖。

半小时解释层附当前报告区间的课程，原始设备分类与时长计算不接收课表覆盖；无设备活动时也归档课程背景。每日复盘附当日、次日课程。历史报告不批量重写，新报告按原有定时流程生成。

页面入口为花园“下一步行动”、目标模式“本周任务”，以及独立 Next Action 页面。均展示今日课程、下一门和可切换的周课表；课程提示隐藏接受和完成按钮。
